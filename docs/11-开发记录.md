## 一、项目简介

「知途 AI 旅行」是一款面向 **1–4 天短途自由行**用户的 **微信小程序**，提供一站式全链路 AI 旅游行程规划。用户通过表单、一句话、截图识图或手动编排四种方式生成行程，系统结合大模型（DeepSeek）与高德地图能力，自动产出含交通、景点、美食、住宿的个性化路线，并支持模板广场、旅游问答、第三方服务快捷跳转与会员订阅。

| 项 | 内容 |
|---|---|
| 项目名称 | 知途 AI 旅行（曾用名：伴游 / 智随伴游） |
| 形态 | 微信原生小程序 + Python 后端 |
| 定位 | 短途自由行 AI 行程规划工具 |
| 开发模式 | 单人独立开发 + AI 代码辅助 |
| 技术栈 | 前端 微信原生小程序（WXML/WXSS/JS）；后端 Python FastAPI + MySQL + Redis；AI 大模型 + OCR |
| 当前状态 | 微信平台审核已通过；工信部 ICP 备案审核中（未正式发布） |

```
│          profile 个人中心 / auth 登录                      │

                │  wx.request (HTTPS /api/xxx, JWT 鉴权)
┌───────────────▼─────────────────────────────────────────┐
│                 FastAPI 后端 (server/)                   │
│  routers: plan / trip / template / chat / auth /         │
│           membership / ocr / user                         │
│  services: plan_service / trip_service / route_service / │
│            image_service / template_service /            │
│            payment_service / vision_client               │
│  AI: DeepSeek LLM（行程生成） / 高德 Web 服务（POI·路径）  │
│       / 视觉模型（识图·待激活）                           │
└───────┬───────────────────────────┬─────────────────────┘
        │                           │
┌───────▼──────┐            ┌─────────▼────────┐
│   MySQL 8    │            │     Redis 7      │
│ 行程/用户/   │            │  限流/缓存/会话   │
│ 模板/订单等  │            │                  │
└──────────────┘            └──────────────────┘
```

**关键设计约定**
- 前端 `config/env.js` 的 `BASE_URL` **不含 `/api`**，所有接口统一以 `/api/xxx` 拼接（前后端必须一致，否则真实模式 404）。
- **2026-10-23 起前端无 mock 模式**：`utils/mock.js` 已删除（它的响应结构和后端漂移，导致收藏页/时间戳/VIP 字段出错），所有页面一律请求真实后端，`BASE_URL` 指向哪看到的就是哪。
- 后端用项目 `venv` 的 Python 启动（`server\venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8010 --reload`），**不可用系统 Python**（缺 `pydantic_settings` 等依赖）。

## 四、UI 设计演进（项目亮点）

用户对界面高级感要求极高，UI 经历了明确的演进路径，是本项目最值得记录的设计决策过程。

### 4.1 风格演进路线

| 阶段 | 方向 | 结果 |
|---|---|---|
| 初版 | 蓝色科技风（默认蓝 `#3B82F6` + 紫渐变） | 被否定，偏"工具感" |
| v3 | 暖色卡片风（米白底 + 大圆角卡片） | 用户评价"太土" |
| iOS 分组列表风 | 毛玻璃导航 + 分组列表 + 系统配色 | 接近，但未达预期 |
| **iOS 26 Liquid Glass** | 液态玻璃材质 + 折射高光 + 大圆角 + 悬浮玻璃 TabBar | **用户选定** |
| **最终落地（方案 C）** | 全屏城市大图 + 半透明 rgba 卡片 | **当前版本，跨平台稳定** |

### 4.2 关键踩坑：开发者工具不支持 `backdrop-filter`
最初按 iOS 26 真液态玻璃实现（导航栏、卡片、TabBar 全部用 `backdrop-filter: blur + saturate`）。但微信**开发者工具模拟器基本不支持 `backdrop-filter`，Android 真机也大多不支持**——在工具里渲染成"接近纯白实底"，用户看到的就是"没变化"，误以为代码没生效。

**解决方案（方案 C）**：不再依赖模糊滤镜，改用**真实的 `image` 全屏背景 + 半透明 `rgba` 卡片浮于其上**，背景大图直接透出来，玻璃质感在开发者工具和真机都稳定可见。
- 全局 `.glass / .card` 类**仍保留 `backdrop-filter`**——在 **iOS 真机**上变为真正的液态玻璃加分项，在工具 / 安卓自动降级为半透明白卡，视觉依旧统一、不崩。

### 4.3 落地范围
- `app.wxss`：重写玻璃设计系统（iOS 语义色 + 主色 iOS 蓝 `#0A84FF` + 玻璃材质类 + 圆角 / 阴影 / 字体层级）。
- `pages/index`：毛玻璃导航、全屏 Hero 透图、2×2 规划入口、快捷服务玻璃圆图标（统一 iOS 蓝细线 SVG）。
- `pages/detail`：整页城市大图背景、景点卡片、行前准备、双栏攻略（拍照 / 美食）、底部操作栏全部半透明浮于图上。
- `pages/trips / member / profile / template`：统一 iOS 蓝调半透明卡片，清除历史残留配色。
- **tabBar 图标重生**：用脚本生成 6 个线性图标（home / trips / profile × 选中蓝 / 未选中灰），替换旧图。
- **图标统一规范**：全部改为 iOS 蓝 1.8px 细线、透明底，杜绝"彩色填充方块 + 五颜六色"的廉价感。

## 五、关键技术问题与解决方案

| 序号 | 问题 | 根因 | 解决方案 |
|---|---|---|---|
| 1 | 保存行程失败「行程 id 格式错误 gen」 | 预览态 `id` 硬编码 `"gen"`，前端当已有 id 传回，`int("gen")` 失败 | `plan.py` 预览态 `id` 改 `None`；`trip_service.save()` 仅整数 id 才更新，否则新建 |
| 2 | 交通段显示「步行28米0x01」 | 高德 instruction 混入 `0x00/0x01` 内部标记 | `route_service` 正则清洗 `\s*0x[0-9A-Fa-f]+` |
| 3 | 城市 / 景点图 500 | loremflickr 复杂关键词不稳定 | 改 `picsum.photos/seed` 兜底，再做「loremflickr → picsum → emoji」三级兜底 |
| 4 | AI 生成一直转圈不跳转 | 高德 Key 配额超限，多景点串行超时累积超前端 60s | 换 Web 服务 Key；POI/路径超时 12–15s→5s；image/transport 调用包 try/except 不阻塞 |
| 5 | app.json「无效 app.json」 | 腾讯地图 AppID 写错（非官方值）；大众点评 AppID 查无确证 | 腾讯地图改官方 `wxca942bbff22e0e51`；大众点评移出白名单；`media.js` 改复制搜索词 |
| 6 | 12306 跳转失败 | 12306 AppID 无法确证 | 改跳携程火车票（`wx0e6ed4f51db9d078`），移出白名单 |
| 7 | 美食攻略全落同一家餐厅 | 仅按时间最近匹配，全天景点都落同一餐 | 后端加 `nearby_food` 字段要求就近；前端 `_matchMeal` 多策略（就近→time_slot→地址相似→时间最近） |
| 8 | 详情页 `wx:key` 重复警告 | 同类节点 key 相同 | `buildTimeline` 给节点加唯一 `tid`，改用 `wx:key="tid"` |
| 9 | 模板列表为空 | 局域网 IP 变更，`BASE_URL` 指向旧 IP | 更新 `BASE_URL` 为当前 IP |
| 10 | 后端启动 `ModuleNotFoundError` | 用系统 Python 缺依赖 | 必须用 `server\venv\Scripts\python.exe` 启动 |
| 11 | 安全：`/docs` 暴露接口 | FastAPI 默认开 Swagger/redoc/openapi | `main.py` 设 `docs_url/redoc_url/openapi_url=None` 关闭 |
| 12 | 模拟器「没变化」 | 开发者工具不支持 `backdrop-filter` + 旧样式缓存 | 改方案 C（不依赖滤镜）；微信工具「清理缓存→全部清理」后重编译 |
