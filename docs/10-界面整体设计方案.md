## 〇、规范统一说明（先解决冲突）

历史文档存在两处配色口径不一致：

- doc5《高保真页面清单》与 doc8《UI 落地规范》：主色 `#4A90D9`
- ZS-UI-001《首页优化稿》：主色 `#3B82F6` / `#60A5FA`

**本方案裁决**：以 `#4A90D9` 为全局品牌主色。理由——12 张高保真页面与交付给开发的规范均以 `#4A90D9` 为准，改动会破坏已交付资产；且该蓝偏暖、更贴合旅行产品的轻松气质。ZS-UI-001 中**不涉色值的视觉质量改进**（柔和页面底色、2px 统一线性图标、轻柔阴影、首页视觉分层）全部采纳为全局原则。

## 一、设计目标与产品定位

- **产品**：面向 1–4 天短途自由行用户的「一站式 AI 行程规划」微信小程序。
- **核心价值**：用 AI 把"想去但不确定怎么安排"的模糊需求，转化为"省心、出片、避坑、省钱"的结构化多日行程。
- **设计目标**：
  1. 让"创建行程"成为首页最显眼、最低门槛的动作；
  2. 用统一视觉语言消除多页面割裂感；
  3. 所有关键操作都有即时、可理解的反馈；
  4. 在微信生态内，按用户既有习惯（卡片浏览、底部 Tab、一键授权）组织信息，降低学习成本。

## 二、目标用户与认知模型（战略层 · 新增）

### 2.1 核心用户画像

| 维度 | 描述 |
| :--- | :--- |
| 人群 | 18–35 岁：大学生、年轻上班族、情侣、亲子家庭 |
| 出行特征 | 短途（1–4 天）、自由行、决策轻、说走就走 |
| 设备习惯 | 移动端优先、重度微信生态、习惯卡片式浏览 |
| 心理状态 | 怕麻烦、怕踩坑、怕花冤枉钱、想拍照好看、对 AI 持"试试看"态度（信任需培养） |
| 专业能力 | 非旅行规划专家，不擅长排时间、算交通、避人流 |

### 2.2 用户心智模型（Mental Model）

用户把"旅行规划"理解为一条朴素链路：

```
想去某城 → 大概几天/和谁 → 想体验什么 → 怎么排进几天里且不踩坑 → 照着走
```

他们期待产品像"一个懂当地、懂天气、懂拍照的旅行搭子"，而不是一个需要填写复杂表单的系统。因此界面必须把**专业规划能力藏在简单入口之后**（渐进披露），首屏只呈现"开始规划"与几种轻量选择。

### 2.3 认知原则在界面中的落地

| 原则 | 界面体现 |
| :--- | :--- |
| **渐进披露**（Progressive Disclosure） | 首页仅给 4 个创建入口 + Banner；高级维度（偏好/交通/预算）收进表单页展开 |
| **希克定律**（Hick's Law） | 创建方式固定 4 种且分主次（核心 2 / 次要 2），避免选择过载 |
| **费茨定律**（Fitts's Law） | 主操作按钮 48px 高、固定底部拇指热区、点击目标足够大 |
| **一致性**（Consistency） | 全站统一组件、2px 线性图标、统一圆角层级（4/8/12/16/24rpx） |
| **即时反馈**（Feedback） | 每次点击、提交、生成都有状态（按压/加载/成功/错误/Toast） |
| **默认与容错**（Defaults & Forgiveness） | AI 生成即给可用方案；支持"对话微调"而非推倒重来；删除二次确认 |

## 三、设计原则（贯穿全站）

1. **核心动作零思考**：首页 Banner + 2×2 入口让"开始规划"一眼可见、一触即达。
2. **主次分明**：用底色、阴影、图标色区分核心功能与次要功能，不平均用力。
3. **卡片即信息单元**：以圆角白卡承载信息，留白与阴影制造空间层次，拒绝平面白板。
4. **统一图标语言**：全站 2px 线性图标，重点模块主蓝、次要模块灰，风格不混杂。
5. **温柔的旅行底色**：页面底色用浅灰蓝 `#F5F6FA`，告别纯白生硬感。
6. **动效服务理解**：动效只用于强化层级与状态（按压、淡入、滑动），不炫技、不卡顿。
7. **微信原生习惯优先**：底部 3 Tab、一键授权登录、卡片流浏览，符合用户既有心智。

## 四、信息架构与导航逻辑（战略层 · 新增）

### 4.1 全局导航骨架

```
知途 AI 旅行
├─ 底部 TabBar（3 个，常驻）
│   ├─ 首页（pages/index）         ← 所有创建入口、模板广场、快捷服务
│   ├─ 我的行程（pages/trips）     ← 已保存行程列表（进行中/历史）
│   └─ 我的（pages/profile）       ← 个人中心、会员入口、设置
│
├─ 首页顶部 Tab（3 个，切换内容）
│   ├─ 首页 | 附近 | 随便问
│   └─ "随便问" → 对话助手（pages/chat）
│
├─ 创建入口（4 种，由首页分发）
│   ├─ AI 表单规划（pages/form）   【核心】
│   ├─ 一句话快规划（pages/quick） 【核心】
│   ├─ 截图识行程（pages/ocr）     【次要·会员倾向】
│   └─ 手动编排（pages/edit）      【次要】
│
├─ 行程闭环
│   ├─ 行程详情（pages/detail）    ← 交通/每日行程/打卡/美食/避坑/对话微调
│   └─ 我的行程（列表）←→ 详情 双向
│
├─ 模板广场
│   ├─ 首页"精选行程模板" → 模板详情（pages/template）
│   └─ 模板详情：使用 / 收藏 / 分享
│
├─ 会员与商业化
│   └─ 我的 → 会员中心（pages/member）→ 套餐/支付弹窗
│
└─ 登录授权（pages/login）         ← 启动页/未登录拦截，微信一键登录
```

### 4.2 导航决策依据

- **底部 3 Tab 而非更多**：遵循微信小程序惯例与费茨定律，核心高频页（逛/我的行程/我）各占一席，避免 5 个 Tab 的拥挤与误触。
- **"随便问"放在首页顶部 Tab 而非底部**：它是"轻咨询"入口，使用频次低于"我的行程"，且需与首页内容并列切换，顶部 Tab 更契合"在同一屏切换不同内容视角"的心智。
- **4 种创建方式统一从首页分发**：用户在首页完成"意图确认"后，再进入对应创建页，避免功能散落各处、找不到入口。
- **详情页是行程闭环中枢**：交通、每日行程、打卡机位、美食、避坑、对话微调全部汇于详情页，确保"生成→查看→优化→保存"不跳脱。

## 七、核心交互流程（战略层 · 新增）

### 7.1 首次使用闭环
```
启动 → 登录授权(微信一键) → 首页
  → 选创建方式（Banner/2×2）
    → 表单 or 一句话 or 截图 or 手动
      → AI 生成（全屏遮罩+进度）
        → 行程详情（查看/微调/保存）
          → 我的行程（沉淀）
```

### 7.2 四种创建方式的选择引导（降低决策成本）
- **核心 2**（首屏上行、主蓝高亮）：AI 表单规划（结构化、可控）、一句话快规划（极速、懒人）。
- **次要 2**（下行、灰边弱化）：截图识行程（会员倾向、识别聊天记录/宣传图）、手动编排（DIY 控权）。
- 引导文案帮助用户"按场景选"：时间紧→一句话；想精细→表单；有现成图→截图；要自己排→手动。

### 7.3 行程详情微调闭环（容错设计）
```
查看详情 → 发现不满意项 → 对话微调区输入指令
  → AI 局部重排 → 变更项黄色高亮闪烁(2s) → 确认/再调 → 保存
```
避免"不满意就重生成"的高成本，符合用户"小修小补"的真实习惯。

### 7.4 会员转化漏斗
```
免费次数用尽（按钮变橙"升级会员解锁无限"）
  → 会员中心（权益对比表 + 月/年套餐）
    → 选套餐 → 底部支付弹窗（遮罩+金色支付按钮）
      → 开通成功（Toast + 状态回写）
```

## 八、主要页面 / 模块设计要点（WF-01 ~ WF-12）

> 每页给出：核心目标 / 布局结构 / 关键交互 / 设计要点（含认知依据）。像素级数值见 doc5 与 doc8。

### WF-01 首页 —— 一切的起点
- **核心目标**：让用户 1 秒内知道"这里能规划行程"并立即行动。
- **布局**：顶部 Tab（首页/附近/随便问）→ 品牌渐变 Banner（开始规划行程）→ 2×2 创建卡片（核心2高亮/次要2弱化）→ 城市选择器 → 快捷服务（5 图标横滑）→ 精选模板（横滑卡片+换一批）→ 底部 3 Tab。
- **设计要点**：核心动作零思考；视觉分层（核心蓝卡带阴影、次要灰边无阴影）；Banner 右下极简插画（透明度 12%）营造旅行氛围；所有卡片 `scale(0.98)` 按压反馈。

### WF-02 AI 表单规划 —— 可控的结构化生成
- **核心目标**：用最少字段收集足够信息，输出精准行程。
- **布局**：导航栏（返回+标题）→ 表单区（出发/目的地城市、天数、人群胶囊、预算、偏好多选、交通、路线风格大卡、备注）→ 固定底部生成按钮（含"今日剩 N 次"）。
- **设计要点**：单选/多选统一胶囊与高亮态；路线风格用"大众/小众"双大卡强化产品差异化卖点；次数为 0 时按钮转橙并引导会员，自然植入商业化。

### WF-03 一句话快规划 —— 极速懒人入口
- **核心目标**：把"想法"直接变成行程，降低填写门槛。
- **布局**：居中 AI 圆形图标 + 标题副标题 → 大输入框 → "💡试试这样说"示例卡（点击填充）→ 生成按钮 → 加载 Lottie（地球旋转+打字效果）。
- **设计要点**：示例卡降低"不知道怎么描述"的焦虑；加载态用趣味动画缓解等待；与表单共用同一套 AI 逻辑，保证输出一致。

### WF-04 截图识行程 —— 识图即规划（会员倾向）
- **核心目标**：从聊天截图/宣传图识别意图，一键成行程。
- **布局**：导航栏（标题+会员标签）→ 相机图标区 → 虚线框上传区（呼吸动画）→ 已传预览（可删）→ 识别按钮（橙）→ 步骤进度（✅/⏳ 竖线连接）→ 完成弹性动画 → 备用"手动输入文本"。
- **设计要点**：上传区虚线+呼吸动画引导操作；步骤进度把"黑盒识别"变为可感知过程，降低不安；提供降级路径（手动输入）保证不卡死。

### WF-05 手动编排 —— 给 DIY 控权用户
- **核心目标**：自由拖拽排路线，完全掌控。
- **布局**：基础信息行（城市+天数）→ 标题输入 → 分日 Tab → 时段标题（🌅上午等）→ 景点卡（拖拽手柄 ☰）→ 添加按钮（虚线）→ 底部搜索栏（全圆角）。
- **设计要点**：拖拽中蓝色边框+抬升阴影+占位虚线，反馈清晰；spring 动画让排序有"实体感"；底部常驻搜索降低找景点成本。

### WF-06 行程详情 —— 行程闭环中枢
- **核心目标**：一站式呈现完整行程并支持优化。
- **布局**：导航栏（标题+操作图标组）→ 概览卡 → 分日 Tab → 日期标题（圆形日期标）→ 时段 → 景点卡（分类色图标）/餐饮卡（暖调）/交通卡（冷调）→ 当日预算 → 避坑提示（浅黄）→ 对话微调区 → 服务跳转入口。
- **设计要点**：用色温区分内容类型（餐饮暖/交通冷）提升扫读效率；避坑提示独立浅黄块突出产品"懂避坑"卖点；对话微调区是闭环关键，变更项黄色高亮。

### WF-07 我的行程 —— 沉淀与再编辑
- **核心目标**：清晰管理已生成行程。
- **布局**：居中标题 → 分类 Tab（进行中/历史，胶囊）→ 行程卡列表（城市+信息行+路线标签+时间）→ 编辑/删除（右滑/文字按钮）→ 空状态。
- **设计要点**：分类降低列表长度焦虑；右滑操作符合微信删除习惯；空状态给明确引导按钮（去规划）。

### WF-08 对话助手（随便问）—— 轻咨询
- **核心目标**：解答旅行疑问、提供行李清单/美食红黑榜等工具。
- **布局**：顶部 Tab（同首页）→ 欢迎区 → 快捷工具卡（行李/美食）→ 消息流（AI 左白 / 用户右蓝）→ 打字状态 → 底部输入（全圆角+发送圆钮）。
- **设计要点**：气泡左右分色符合主流 IM 心智；流式输出+光标增强"AI 在思考"的真实感；快捷工具把"问"变成"用"。

### WF-09 个人中心 —— 身份与入口聚合
- **核心目标**：呈现用户资产与通往设置/会员的入口。
- **布局**：渐变用户信息区（头像+昵称+统计）→ 会员入口金卡 → 功能菜单列表（图标+标题+箭头）→ 版本号。
- **设计要点**：渐变头部强化品牌温度；会员金卡在个人中心前置，提升转化曝光；菜单左图标右箭头是微信标准范式，零学习成本。

### WF-10 会员中心 —— 商业化主战场
- **核心目标**：清晰传达权益，促成开通。
- **布局**：导航栏 → 金色 Banner（皇冠+标题）→ 权益对比表（免费✕/会员✓）→ 月/年套餐卡（年卡"性价比"角标+选中圈）→ 支付按钮（金渐变）→ 底部支付弹窗。
- **设计要点**：对比表用对勾/叉直观放大"值"；年卡角标制造锚定；支付弹窗底部滑入+遮罩聚焦决策。

### WF-11 模板详情 —— 复用他人灵感
- **核心目标**：查看并使用/收藏/分享模板。
- **布局**：导航栏（收藏/分享）→ 标题卡（城市 emoji+标题）→ 信息行 → 简介区 → "使用此模板"主按钮 + "加载后自定义"次按钮。
- **设计要点**：双按钮区分"直接用"与"改了用"两种意图；次按钮降低"套用后想改"的心理门槛。

### WF-12 登录授权 —— 低摩擦准入
- **核心目标**：微信一键登录，合规展示协议。
- **布局**：渐变背景 → Logo（弹性出现）→ 应用名+Slogan → 微信绿登录按钮（全圆）→ 协议勾选 → 权益列表。
- **设计要点**：微信绿按钮借助平台信任降低注册阻力；协议勾选合规且默认未勾（防误授权）；Logo 弹性动画建立第一印象亲和力。

## 十一、无障碍与适配

- **对比度**：正文 `#666` on `#FFF` ≈ 5.7:1，满足 WCAG AA；主蓝按钮白字对比充足。
- **触控目标**：所有可点元素 ≥ 48rpx（24px）热区，满足 44px 物理建议。
- **安全区**：底部留 `env(safe-area-inset-bottom)`，状态栏用 `wx.getWindowInfo().statusBarHeight` 动态取，不写死。
- **rpx 自适应**：所有尺寸 ×2 换算；超大屏字号仍清晰。
- **动效降级**：尊重系统"减少动态效果"偏好，关键功能不依赖动画。
