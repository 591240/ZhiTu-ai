## 一、文档概述

### 1.1 产品简介

知途 AI 旅行是一款面向 1-4 天短途自由行用户的 AI 智能行程规划微信小程序。产品整合大语言模型行程生成、OCR 截图识别、旅游智能问答、第三方服务快捷跳转等能力，解决旅游信息碎片化、规划与消费服务割裂的行业痛点，实现"需求输入 → AI 生成行程 → 配套服务预订"全链路闭环。

### 1.2 术语表

| 术语     | 说明                                                     |
| :------- | :------------------------------------------------------- |
| LLM      | 大语言模型，用于行程生成、对话微调、旅游问答               |
| OCR      | 光学字符识别，用于解析攻略截图中的文字                     |
| CPS      | 按销售分成，第三方服务分销佣金模式                         |
| 跨小程序跳转 | 微信小程序间跳转 API，直达美团、携程等第三方服务页面      |
| 大众路线 | AI 生成热门景点为主的常规观光路线                          |
| 小众路线 | AI 生成本地冷门景点为主的深度游路线                        |
| 行程模板 | 预制成熟城市短途行程，可一键加载使用                        |

### 1.3 需求范围

本文档覆盖 MVP 阶段全部功能需求，包含：用户系统、行程规划（四种创建模式）、行程管理、模板广场、旅游智能问答、快捷服务跳转、会员体系、个人中心。

## 二、目标用户与场景

### 2.1 用户画像

#### 用户画像 1：亲子家庭游客

- **年龄**：28-40 岁
- **出行特征**：1-3 天城市周边短途，偏好低强度、儿童友好路线
- **核心需求**：生成温和亲子路线，一键跳转酒店、亲子景区门票预约
- **典型场景**：周末带娃出游，需要快速规划包含亲子景区、适合儿童饮食的行程

#### 用户画像 2：情侣出游人群

- **年龄**：20-35 岁
- **出行特征**：周末城市打卡、小众景点、夜景美食，预算中等
- **核心需求**：兼顾网红打卡 + 小众路线，整合餐厅、观影、打车服务
- **典型场景**：周末情侣出游，需要网红打卡点 + 小众隐藏景点组合

#### 用户画像 3：学生结伴群体

- **年龄**：18-24 岁
- **出行特征**：平价穷游，偏爱免费景点、夜市，出行频次高
- **核心需求**：低成本路线生成，海量城市行程模板免费使用
- **典型场景**：假期与同学结伴出游，预算有限，需要免费景点组合

#### 用户画像 4：中老年休闲游客

- **年龄**：40-60 岁
- **出行特征**：少徒步、多平缓观光，重视预约、交通便捷性
- **核心需求**：生成低强度休闲路线，简化复杂操作，直达景区预约入口
- **典型场景**：退休后周边游，需要低强度路线和便捷的预约入口

### 4.2 行程规划

#### FR-P01 AI 智能表单规划

| 属性     | 内容                                                       |
| :------- | :--------------------------------------------------------- |
| 需求编号 | FR-P01                                                     |
| 优先级   | P0                                                         |
| 描述     | 用户通过填写结构化表单，AI 生成个性化分日行程               |
| 前置条件 | 用户已登录；当日剩余生成次数 > 0（免费用户）或为会员         |
| 输入参数 | 目的地城市、出行天数（1-4 天）、出行人群（亲子/情侣/学生/中老年/朋友/其他）、预算档位（经济<500/舒适500-1500/高端>1500）、游玩偏好（自然风光/人文历史/美食探店/网红打卡/休闲度假，可多选）、交通方式（自驾/公共交通/步行/混合）、路线风格（大众观光/小众深度）、特殊备注 |
| 主流程   | 1. 用户在首页点击"开始规划行程"<br>2. 选择"AI 智能表单规划"<br>3. 填写表单各字段<br>4. 点击"生成行程"<br>5. 前端校验必填项<br>6. 调用后端 `/api/plan/form` 接口<br>7. 后端封装 Prompt 调用 LLM<br>8. LLM 返回结构化分日行程 JSON<br>9. 前端展示行程预览页<br>10. 用户可保存或对话微调 |
| 输出格式 | 结构化分日行程，每天包含：日期、时段（上午/下午/晚上）、景点列表（名称/地址/游玩时长/门票价格）、餐饮推荐（餐厅名称/人均/特色菜）、交通建议、当日预算、避坑提示 |
| 异常流程 | 必填项未填 → 表单校验提示；次数用尽 → 引导开通会员；LLM 超时 → 提示重试 |
| 验收标准 | 行程内容与用户输入参数匹配；景点信息合理；分日结构清晰；大众/小众路线风格有明显差异 |

#### FR-P02 一句话快规划

| 属性     | 内容                                                       |
| :------- | :--------------------------------------------------------- |
| 需求编号 | FR-P02                                                     |
| 优先级   | P0                                                         |
| 描述     | 用户用自然语言一句话描述出行需求，AI 自动拆解参数生成行程    |
| 输入参数 | 自然语言文本，如"下周末想带5岁娃去杭州玩两天，预算800，喜欢自然风景" |
| 主流程   | 1. 用户在首页选择"一句话快规划"<br>2. 输入自然语言描述<br>3. 点击"生成行程"<br>4. 调用后端 `/api/plan/quick` 接口<br>5. 后端先用 LLM 提取结构化参数<br>6. 再用提取的参数生成行程<br>7. 返回行程预览 |
| 异常流程 | 输入过短/无意义 → 提示补充信息；LLM 解析失败 → 提示重试       |
| 验收标准 | AI 能正确提取目的地、天数、人群、预算等关键参数；行程与用户意图匹配 |

#### FR-P03 截图识行程

| 属性     | 内容                                                       |
| :------- | :--------------------------------------------------------- |
| 需求编号 | FR-P03                                                     |
| 优先级   | P1（会员功能）                                              |
| 描述     | 用户上传网络攻略截图，OCR 识别文字后由 LLM 转换为可编辑行程  |
| 前置条件 | 用户为付费会员                                              |
| 输入参数 | 攻略截图图片（支持 jpg/png，单张 < 5MB）                      |
| 主流程   | 1. 用户选择"截图识行程"<br>2. 拍照或从相册选择图片<br>3. 上传图片到后端<br>4. 后端调用 OCR API 提取文字<br>5. 调用 LLM 将文字清洗并结构化为标准行程<br>6. 返回可编辑行程预览<br>7. 用户可手动修正后保存 |
| 异常流程 | 图片格式不支持 → 提示重新选择；OCR 识别失败 → 提供手动文本录入；LLM 解析失败 → 提示重试 |
| 验收标准 | OCR 能识别中英文混合文本；行程结构与表单规划格式一致；支持用户手动修正 |

#### FR-P05 行程对话微调

| 属性     | 内容                                                       |
| :------- | :--------------------------------------------------------- |
| 需求编号 | FR-P05                                                     |
| 优先级   | P0                                                         |
| 描述     | 用户在行程详情页通过对话指令微调已生成的行程                 |
| 输入参数 | 自然语言指令，如"把第二天的景点换成西湖周边""增加一个吃晚饭的地方""预算减少200" |

| 验收标准 | 微调指令被正确执行；未修改部分保持不变；支持保存为新版本      |

## 五、非功能需求

### 5.1 性能需求

| 指标             | 要求                           |
| :--------------- | :----------------------------- |
| 页面加载时间     | 首屏 < 2 秒                    |
| LLM 行程生成时间 | < 15 秒（含流式输出）           |
| 问答响应时间     | < 10 秒（含流式输出）            |
| API 接口响应     | 普通接口 < 500ms               |
| 并发支持         | 100 QPS（冷启动阶段）            |

### 5.2 兼容性需求

- 微信基础库版本 ≥ 2.14.0
- 适配 iOS 12+ / Android 7.0+
- 适配 iPhone SE ~ iPhone 15 Pro Max 全系列屏幕
- 适配主流 Android 机型

### 5.3 安全需求

- 所有 API 请求携带 token 认证
- 用户敏感信息（openid）不暴露给前端
- 微信支付签名校验
- 接口防重放攻击

### 5.4 可用性需求

- 服务可用性 ≥ 99.5%
- LLM 接口异常时有降级提示和重试机制
- 离线状态下可查看已缓存行程

## 八、附录

### 8.1 交互设计规范

- 按钮点击反馈：缩放 0.95 + 透明度变化
- 页面切换：右进左出动画，300ms
- 加载状态：骨架屏 + 加载动画
- 弹窗：底部滑出，圆角 16px
- 颜色规范：主色 #4A90D9（蓝色），辅助色 #FF6B35（橙色），背景色 #F5F6FA

### 8.2 异常处理规范

| 异常类型     | 处理方式                           |
| :----------- | :--------------------------------- |
| 网络异常     | Toast 提示"网络不佳，请重试"        |
| 登录过期     | 自动跳转登录页                      |
| 接口异常     | 展示空状态 + 重试按钮               |
| LLM 超时     | 提示"生成中，请稍候"+ 重试按钮       |
| 次数用尽     | 弹出会员引导弹窗                    |
